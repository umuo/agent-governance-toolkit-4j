# 流式增量护栏需求

状态：2026-10-19 已实现首阶段局部字面护栏，验证范围与未覆盖项见 [实现验收](streaming-guardrails-verification.md)。本页保留需求和初始选型记录；实际 API、固定容量与支持矩阵见 [使用说明](guarded-streaming-guide.md)。不预设发布版本。

## 目标与当前基线

在不等待全文生成的情况下，对流式文本执行有界局部检测，阻止受支持的字面拒绝规则命中的内容外发，并在拒绝后及时终止受控流。安全保证限定于已声明的局部规则，不承诺任意正则或整段语义风险零泄露。

当前 `StreamDelivery.REALTIME` 将增量作为未经最终检查的预览，`STRICT` 在完整检查后交付。`StreamingCollector` 负责计量、预览与 provider handle，`GovernedStreamingChatModel` 复用模型治理，`GovernedPublisher` 负责 Reactive 交付和预取。Core 当前不依赖 Reactor，`ContentRule` 提供字面拒绝及全文替换，`PolicyDecision` 使用 `ALLOW / DENY / TRANSFORM`。

本需求承接 [原生兼容性扩展](native-compatibility-requirements.md) 与 [原生边界与资源优化](native-optimization-requirements.md)。[v0.3 流式需求](streaming-requirements.md) 继续作为严格缓冲历史基线。

## 范围与交付模式

新增显式交付模式，建议命名 `StreamDelivery.GUARDED`；最终名称随实现确定。三种模式必须在文档和配置中清楚区分：

| 模式 | 增量交付条件 | 保证与限制 |
| --- | --- | --- |
| REALTIME（已有） | 收到增量即可预览 | 保留当前契约；最终检查不能撤回预览 |
| GUARDED（新增） | 局部检查通过，且不属于未决尾部 | ENFORCE 下保障已声明的局部字面拒绝规则；最终检查仍可能拒绝已部分交付的回答 |
| STRICT（已有） | 完整响应及交付前治理通过 | 保留当前完整缓冲与最终改写能力 |

原生入口默认 `REALTIME`、旧 Builder 与单独模型装饰器的既有默认契约保持不变。新增能力必须显式启用；不得悄悄把严格模式降级为局部检查。

第一阶段覆盖文本 handler、TokenStream、文本 Flow.Publisher 及现有可选 Reactor 适配。只对响应正文提供局部保证；thinking、工具参数、raw event 和多模态内容不得借新模式成为原文旁路。无法安全投影的事件形态须在装配时明确拒绝，非正文通道继续按适配器的现有治理契约处理。

第一阶段实现有限词表的字面拒绝、微批触发、跨块检测、安全尾部暂存、终止传播与审计。任意正则、流式替换、远程语义模型和句段级放行属于后续扩展。不得宣称增加缓冲器便已经实现语义检测。

## 核心行为

### 微批检测与安全交付

- Core 增加按流实例隔离的 `ChunkBufferEngine`（建议名），采用不依赖 LangChain4j、Spring 或 Reactor 的状态机。模型回调输入的是任意长度文本片段，不能假定一次回调等于一个字符或一个 Token。
- 达到字符阈值、遇到配置边界、达到最大等待时间、流结束，任一条件触发检测。大片段须分段处理，不得先无限拼接再检查额度。
- 将“检测上下文”和“尚未交付文本”分开管理。Overlap 用于跨片段匹配；暂存尾部用于防止尚未完成的敏感词前缀提前外发。不能只保留已发送文本用于下一次检测。
- 有限词表最大长度为 `L`，保守实现保留最多 `L−1` 个 UTF-16 code units 的未决尾部；也可按自动机状态保留所有可能命中词的前缀后缀，但必须提供等价验收。多种检测器组合时按最保守的放行边界推进。
- 例：禁词 `ABCDEF`，输入 `普通文本ABC`、`DEF后续`，即使中间发生计时触发，应用也只能收到安全前缀，不能收到该命中词的任何字符。对敏感词出现位置的保证不等于禁止安全文本包含相同的单个字母。
- 标点只触发检测，不清空匹配状态；禁词可以跨标点、跨微批或长于微批阈值。计时触发不能强行释放未决尾部；因此最大等待时间是检测调度目标，不是任意字符的交付延迟上限。
- 第一阶段采用与 `String.contains` 一致的大小写敏感字面匹配，不自动忽略空格、做 Unicode 归一化或同形字识别。UTF-16 计量沿用现有限额；交付不得拆开有效代理对，跨回调的代理对须正确拼合。
- 正常完成时，先核对最终权威响应并执行必需的完整检查，再检查、释放剩余尾部。失败、拒绝或取消时丢弃未交付内容；不得按正常结束 flush。

### 策略与最终响应

- 复用可信身份、会话、固定策略版本和 `EnforcementMode`，不从模型片段建立授权信息。原需求中的 `BLOCK` 在本项目映射为 `DENY`，不新增另一套裁决枚举。
- 局部检查是附加交付门，不替代 `post_model_call`、`output`、工具权限、审批、预算或必需审计。完整模型检查通过之前，不向框架提前放行可触发工具执行的事件。
- 局部词表与现有策略配置必须有明确绑定，记录规则 ID、策略版本、适用流及干预阶段；只有显式声明为可增量检查的字面规则进入局部检测。任意自定义 `PolicyEvaluator` 不得被自动当作可流式检测器。
- 原有 `ContentRule` 在结构化投影中的其他字段匹配继续由完整检查执行，不把正文局部检查声称为覆盖所有投影。局部检测不能重复计入模型/工具调用预算，也不把每个微批伪装为一次完整模型调用。
- 第一阶段 `GUARDED` 不支持流式 `TRANSFORM`。已知需要最终正文替换的配置组合在装配时拒绝，并提示使用 `STRICT`；自定义策略运行时产生与已交付正文冲突的改写，则终止，不重放改写全文或继续成功完成。
- provider 最终正文应与本轮增量拼接结果一致；不一致时拒绝继续交付或报告成功。需要这类 provider 的兼容性时使用 `STRICT`，不能悄悄切换交付语义。此检查无法撤回已发送内容。
- `EVALUATE_ONLY` 记录局部裁决，继续原值，不宣称已阻断；容量上限、生命周期和协议故障仍终止。对外示例中的局部阻断保证必须标注 `ENFORCE` 前提。
- 每轮模型调用独立重置检测状态和偏移量，保留会话/调用关联；不得跨工具轮次拼接词表匹配。中间轮次正文属于已交付预览，完整输出失败或工具副作用均不能回滚这些内容。

### 终止、并发与容量

- `DENY` 后先禁止后续交付、清空待发送队列和计时任务，再通过现有会话故障终止路径停止后续模型/工具动作，并尝试取消已取得的 provider handle 与 Publisher subscription。
- 尚未取得 handle 或 provider 不支持取消时，只保证受控流终止与晚到事件不交付；后来取得 handle 时仍尝试取消。不得承诺一定停止网络生成或计费。
- 增量、计时、完成、取消、拒绝和会话期限的竞争须串行化状态变化，保证文本有序、无重复，终止只生效一次。已开始执行的应用回调不能撤回；终止后不能开始新的文本/成功回调。
- 错误通过稳定 `GovernanceException` 错误码和现有 onError/onError signal 传递，不附带敏感原文或 provider 异常正文；客户端主动取消沿用现有取消契约。SSE/WebSocket 错误帧由宿主或协议适配器映射，Core 不依赖传输协议。错误终止不得等待下游额外 demand。
- 保留 `StreamingLimits.maxCharacters / maxEvents` 的现有累计计量；检测时重扫 overlap 不重复计作 provider 输入。模型流和服务聚合仍共享服务所选额度，不能增加无上限的历史正文副本。
- 检测缓冲、待交付队列、词表大小、最大词长和调度任务均须有界。慢消费者遵守现有 credit/prefetch；推送型 provider 不能暂停时，达到缓冲限额即失败关闭，不用无限队列补偿。
- 完成、拒绝、取消、关闭及过期后释放缓存、匹配状态与任务。计时线程恢复可信会话绑定；不得在 provider 回调线程执行远程语义分析或阻塞策略调用。

## 配置与集成方向

以下保留初始配置契约与建议默认值；已实现 API 及固定上限以使用说明为准。统一从服务 Options 传入；Starter 使用 `agt.langchain4j` 下对应配置，服务专属 Options 优先，不另建独立全局配置文件。

| 配置语义（建议名） | 建议默认与约束 |
| --- | --- |
| delivery | 既有默认保持不变；显式选择 GUARDED 才启用 |
| chunkCharacters | 20 UTF-16 code units；正整数，不超过检测缓冲上限 |
| boundaries | `，。！？\n`；空集合表示只由长度/时间/结束触发 |
| maxWait | 50 ms；必须为正且有限；从首个待检测字符开始计时，不能被后续字符无限延期 |
| maxBufferedCharacters | 4096 UTF-16 code units；须容纳触发微批及未决尾部，并受现有累计上限约束 |
| localRules | 显式选择的规则集合；GUARDED 下缺失、为空或无法证明局部匹配能力时拒绝装配 |
| overlap | 从规则最大词长或匹配器能力推导，不允许宿主任意调小造成漏判 |

实现时须固定并公开词表总量、最大词长及配置数值范围，覆盖非法值和容量不足的装配失败测试。当前默认值只是起点，性能验证后可在实现记录中调整并说明依据。

扩展 `AiServiceOptions` 时保留现有三参数构造路径和默认值；Starter 属性与 Java API 使用同一份校验。旧 Builder、低层模型装饰器和不支持新模式的入口必须明确记录支持矩阵，不得静默忽略配置。

审计复用 `AuditSink`，区分局部检测与最终检查，关联会话、模型轮次/调用 ID、策略版本、规则 ID、裁决、逻辑文本偏移、检测/终止耗时。重叠扫描不得重复生成同一次命中的业务审计。默认不存原文或敏感词；必需局部审计未确认时不放行对应文本，审计失败关闭路径。

## 初步 spike 与选型（规格阶段历史记录）

本次已检查项目上述实现与上游文档；尚未新增依赖、运行匹配器原型或性能基准。以下区分可复用机制与实现前验证项：

| 候选 | 已核对的能力与取舍 | 本需求决策 |
| --- | --- | --- |
| 项目现有状态机、会话、Publisher credit | 已有生命周期、容量、取消与完整治理，Core 无 Reactor 依赖 | 复用；只增加局部检测和安全放行状态 |
| [LangChain4j 输出护栏](https://docs.langchain4j.dev/tutorials/guardrails/) | 官方文档描述完整响应后检查并重放，不能直接提供本需求的局部交付门 | 保留现有适配，不用原生输出护栏替代本需求 |
| [Reactor Flux](https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Flux.html) | 提供 bufferTimeout 等操作符；按元素缓冲不能独立解决字符边界、敏感前缀和跨块泄露 | Reactor 入口复用适配层；Core 不新增强制依赖 |
| [robert-bor/aho-corasick](https://github.com/robert-bor/aho-corasick) | Apache-2.0，Java 多词匹配，提供 parseText/containsMatch；文档未证明跨调用状态续接能力 | 作为有限窗口重扫的复用候选；不在规格阶段锁定版本 |

实现前对 AC 候选核查发布与维护状态、固定版本源码、Java 17 兼容性、依赖和许可证，并验证跨块、重叠词、最大词长和内存边界。若公开 API 仅支持完整窗口，优先验证有限窗口重扫是否满足预算；不访问私有状态或复制整套治理框架。无论匹配器选哪种实现，暂存尾部、放行边界和终止状态仍由本项目负责。

## 验收标准

以下为原始验收目标；执行结果及证据单独记录在实现验收页。

| 编号 | 可观察行为与验证方式 |
| --- | --- |
| SG01 模式兼容 | 原生默认 REALTIME、显式 STRICT、旧 Builder 与三参数 Options 行为回归；新增模式须显式启用；Starter 覆盖和服务间配置隔离 |
| SG02 流式价值 | 可控 provider 暂停在完成事件之前，足够长的安全正文已有部分交付；STRICT 同样输入仍零交付；正常完成拼接结果有序且无重复 |
| SG03 任意切分 | 对禁词逐一枚举所有两段切分及逐字符、多块切分，核对跨微批、跨标点和长于 20 字符的禁词均命中；含重叠词和同一回调内多个批次 |
| SG04 零命中词泄露 | `普通文本ABC` / `DEF后续` 配合禁词 `ABCDEF`，在每个切分点插入计时、下游拉取；命中区间零字符外发；只保留已发送 overlap 的错误实现必须无法通过 |
| SG05 时间与尾部 | 虚拟时钟验证低速安全文本触发检测；未决前缀在超时后仍保留；短回答完成后正确 flush；拒绝/异常/取消不 flush；无后续字符不反复空调度 |
| SG06 字符与配置 | 中文、换行、有效代理对跨回调拼合，不因重扫重复计量；空词表/空词、非法额度、最大词长超缓冲、非增量规则组合均提前失败 |
| SG07 竞争与清理 | 拒绝、取消、关闭、过期、完成、计时竞争只产生一个终态；handle 迟到仍取消，provider 晚到事件零交付；缓存和定时任务可验证释放 |
| SG08 背压与入口 | 同一规则经 handler、TokenStream、Flow.Publisher、可选 Flux 得到相同正文决策；慢消费者有界、超限失败、无 demand 也传递错误；非正文通道无原文旁路 |
| SG09 完整治理 | post_model/output 拒绝仍失败，最终正文不一致或运行时改写冲突不能成功；已知替换配置提前拒绝；不重复交付全文；EVALUATE_ONLY 记录但不拦截 |
| SG10 工具与会话 | 每轮独立检测，拒绝后无后续工具/模型动作；完整检查前工具事件无副作用；仍覆盖工具权限、审批、预算、身份/租户隔离和自动会话关闭 |
| SG11 审计 | 局部/最终裁决可区分且版本、轮次、偏移可关联；原文不进入默认日志；重扫不重复审计；必需审计失败无对应文本交付 |
| SG12 集成与资源 | 固定项目 LangChain4j 版本的本机 SSE 测试验证分片拦截与取消；JDK 17/21 相关及既有回归通过；文档严格构建通过 |

性能验收记录首块延迟、检测耗时、吞吐、最大缓冲占用，比较 REALTIME / GUARDED / STRICT，在固定词表规模、字符速率、并发流数和慢消费者条件下给出结果。50 ms 为建议调度配置，不作为未经测量的端到端 SLA；未运行压测不得声称生产性能提升。

## 后续：语义慢轨

可增加按句/段检查的慢轨，但必须显式选择交付契约：检查通过后放行相应句段，或允许预览后异步检测并仅停止后续输出。前者承担等待延迟，后者不保证已发送内容安全，二者不得共用模糊的“已检查”标签。

慢轨落地前另行明确上下文窗口、句段上限、超时、并发额度、乱序结果处理、失败关闭及文本外发隐私；与快轨组合时只能放行所有必需检查均通过的前缀。最终全文检查继续保留，不以本需求承诺通用语义风险零泄露。
