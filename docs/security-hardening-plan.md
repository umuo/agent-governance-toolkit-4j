## 现成方案检查

现有 `PolicyEvaluator` 可扩展授权来源；本轮检查了 [OpenFGA](https://github.com/openfga/openfga)（Apache-2.0，外部关系授权服务）和 [SpiceDB 的限时关系](https://authzed.com/docs/spicedb/concepts/expiring-relationships)。它们可处理持久权限关系，不能直接替代本 SDK 的 JVM 会话、预算预占、异步取消与结果交付机制。本轮复用 `HostSession`，不为本机生命周期引入外部授权服务；跨服务权限存储选型仍待接入验证。

## 显式本机委托接口

`control.openDelegatedSession(parent, childIdentity[, execution])` 返回 detached 会话，使用时在工作线程 `bind()`，结束时 `close()`。

- 父子必须属于同一个 `AgentControl`；tenantId、principalId 必须相同，子权限必须为父权限子集。Agent ID 可以不同。
- 父会话对象是宿主传递的能力，不能用 traceId、parentRunId 或模型输出创建授权关系。
- 子会话仍执行同一运行时的正常策略、工具审批、预算及审计。默认普通 `openSession` 保持独立，不按 ThreadLocal 自动继承委托。
- 父会话关闭、撤销、失败或到期后，子孙不能开始新的受控操作或交付结果；受追踪异步调用会收到终止通知。子会话拒绝不自动终止父会话或兄弟。
- 子会话期限不超过祖先剩余期限，根任务深度通过 `TaskLimits.maxDelegationDepth` 配置（范围 0–32），活跃会话数通过 `maxConcurrentSessions` 配置且包含根会话。普通根会话默认分别为 32 和 128。
- 撤销不能回滚已发生副作用，也不保证强制停止任意 Java 代码或未接入的外部进程。跨进程签名凭证另见下文与[远端委托指南](remote-delegation.md)；Token/费用约束需要显式配置宿主计量契约与价格表。

## 根任务共享预算

`openTaskSession(identity, new TaskLimits(new BudgetLimits(8, 5, 120000), 10, 3, 1))` 创建 detached 根会话：整棵显式委托树共享 8 次模型调用、5 次工具调用、10 次数据调用、120 秒期限、最多 3 个活跃会话（含根）和 1 层子会话。普通根会话使用运行时调用/数据预算作为共享上限。单会话原有限额仍同时生效。

预算在受控操作进入前原子预占，通过策略与准备后提交；准备失败、拒绝或取消释放未提交配额，已进入执行的尝试不退回。子会话关闭后保留已提交消耗，不能通过重建子会话重置总预算。根任务之间隔离。`session.taskSnapshot()` 可查询共享计数、任务 ID、活跃会话数与限额。活跃会话数限制治理会话，不等于 OS 线程、CPU 或下游 HTTP 并发数。

默认本机预算是单 JVM 内存状态，不支持进程重启恢复；实验级跨服务调用配额需显式启用 agt-delegation。Token/费用通过显式 UsageLimits 与计量器接入，见 [用量预算指南](model-usage-budget.md)。取消完成表示停止受控交付及请求取消，不是副作用回滚或所有底层任务已确认退出。多 Agent 演示中的根任务预算与子 Agent 委托信息以节点正文记录，沿用现有折叠与大窗口查看。

## 任务与资源级委托

`DelegationScope` 位于 `io.agt.core.delegation`，宿主在创建根任务时可传入：

```java
var scope = new DelegationScope("customer-summary", true,
        Map.of("lookup", ParameterRule.object(
                Map.of("tenant", ParameterRule.string("tenantId")), "tenant")),
        Map.of(actualPartition, Set.of(DataOperation.RETRIEVE)));
try (var root = control.openTaskSession(identity, limits, execution, scope);
     var child = control.openDelegatedSession(root, childIdentity, childExecution, narrowerScope);
     var binding = child.bind()) {
    // 调用受控模型、工具或已经绑定 actualPartition 的检索器。
}
```

`taskName` 是宿主认可的任务标签，不解析提示词、不证明模型语义符合任务。具体限制由工具名、闭合参数规则、模型许可和数据实例/操作体现。没有列出的工具、实例或操作默认拒绝；即使基础策略允许也不能绕过。数据资源按完整宿主描述符匹配，只有相同租户或相同资源名不够。源 handle 必须仍由宿主绑定到实际分区。

省略子 scope 时继承原 scope；显式传入时，任务标签不能变化，工具/数据操作/模型能力不能新增。每次调用还会检查全部祖先参数规则的交集，因此声明更宽的参数规则不能扩大实际权限。参数改写后再次检查。`equalsContext` 在每一层按该 scope 的签发身份求值，继承时不会随子 Agent ID 改变。基础策略仍按实际调用身份运行。

这些能力约束属于会话授权边界，即使基础策略处于 `EVALUATE_ONLY` 也会强制执行；拒绝以 `delegation_*_denied` 原因码审计。它们不是内容规则的观察模式。`AgentTracer.governedDelegated` 支持传入 scope；当前演示的研究 Agent 仅可调用 lookupFacts，核验 Agent 仅可调用内部投递参数的 deliverDigest，详情显示任务标签和工具参数范围。

本轮继续复用既有 `ParameterRule`、`DataResource` 和审计，不引入新的表达式语言；[Cedar 的主体/动作/资源/请求上下文划分](https://docs.cedarpolicy.com/auth/authorization.html)可作为后续外部策略适配参考，当前没有声称已集成 Cedar。

## 根任务数据流与动作顺序

`io.agt.core.flow.DataFlowPolicy` 可放入 `TaskLimits` 第五个参数。四参数构造器继续兼容，默认不启用信息流规则。所有配置均由宿主提供，模型或工具返回的 `public`、`trusted` 字段不会覆盖配置。

```java
var flow = new DataFlowPolicy(
        Map.of(actualPartition, DataLabel.CONFIDENTIAL),
        Map.of("readCustomer", DataLabel.CONFIDENTIAL),
        Map.of("send", new DataFlowPolicy.SinkRule(
                DataLabel.CONFIDENTIAL, "destination",
                Map.of("internal", DataLabel.CONFIDENTIAL, "external", DataLabel.PUBLIC),
                Set.of("review"))),
        Set.of("review"), // 已审核且不是来源/出口的工具
        DataLabel.PUBLIC, // 宿主对任务输入的分级
        DataLabel.CONFIDENTIAL, // 宿主配置的模型服务允许接收等级
        DataLabel.CONFIDENTIAL); // 调用方输出允许接收等级
var limits = new TaskLimits(new BudgetLimits(8, 5, 120000), 10, 3, 1, flow);
```

等级依次为 PUBLIC、INTERNAL、CONFIDENTIAL、SECRET。根任务的子孙共享同一个单调上升的等级；已接触机密来源后，重新声明参数为公开、关闭读取子会话、改写/编码内容都不会降低等级。该策略保守地限制整棵任务，不做字节级污点跟踪，可能阻止实际上不含机密的后续外发；应由宿主拆分独立且确实不共享敏感上下文的任务，不提供模型可调用的降级接口。

资源按完整 DataResource 描述符分类，读取时提升任务等级，写入低等级资源时拒绝。工具必须出现在来源、出口或 neutralTools 注册表中，新增未分类工具默认拒绝；neutralTools 是宿主对工具行为的声明，不能把实际外发工具随意标成中性来获得保护。模型和最终输出分别按宿主配置的可信服务与调用方等级检查，不自动识别真实 Provider 或收件人身份。

前置工具必须实际执行成功、通过后置检查且审计写入成功才登记。依赖是任务内的工具级先后约束，不是可消费的一次性授权或资源参数级事务；逐动作审批仍独立生效。来源等级在实际执行提交前登记，发生异常仍保守保留，防止已经读取部分内容的失败被当成未读取。

预检查与改写后检查之外，模型、工具和数据访问在提交时原子重验；准备阶段与另一个子 Agent 的敏感读取交错时不会用旧等级放行。已提交、已发生的外发不能回滚。未接入的直接 HTTP/SQL/文件操作不受本 SDK 控制；默认标签与依赖状态仍在本机根任务中保存；显式启用 agt-delegation 可跨服务共享，启用 agt-provenance 可持久保存实例等级与来源版本。完成步骤仍属于活跃任务，不在任务重启后恢复。

网页“ASI02 → 工具链外传”已采用通用信息流机制：工具参数本身同时允许 internal-demo/external-demo，读取内部便签将根任务提升为 CONFIDENTIAL，之后外部投递以 `data_flow_egress_denied` 拒绝；未读取机密时允许向同一外部目的地发送公开消息。完整过程附带“根任务数据流与敏感等级”。这是合成数据实验，不连接真实外部接收器。

实时模式仍保留“内容尚未最终检查”的预览语义，但新增的数据等级约束在流式文本、思考/原始增量、TokenStream 回调与 Reactive 交付入口强制检查；不能利用提前预览绕过低等级调用方的限制。严格模式也会在完整结果交付时检查。同步回调与实时/严格订阅的回归测试验证低等级接收器收到的内容为零。

## 分布式用量预算阶段

`UsageLedger` 允许模型适配器沿用同一套计量与调用流程，远端每次预占/dispatch/结算经在线权威服务执行，不创建各自的本机余额。交接保留历史 settled 消耗并绑定价格配置；未决本机模型调用未完成时拒绝交接，保留原任务。用量未知、接收进程崩溃、祖先失联都会保留已经 dispatch 的预占并冻结所有分支。发送端旧快照不可被误读为全局余额。
