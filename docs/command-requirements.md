# v0.5 ASI05 固定命令执行需求

本阶段加强意外代码执行风险的执行前控制，提供可运行、可验证的受信任命令入口。无需额外服务，继续使用 Java 17 与 LangChain4j 1.20.0。

## 范围与验收

- 宿主以 FixedCommand 注册工具名称、绝对程序路径、可信 SHA-256、固定工作目录与 argv 模板。模型只能提交必填的字符串枚举选项，不能提供程序、任意脚本、环境变量、工作目录、stdin 或自由参数列表。
- 沿用工具默认拒绝、权限、参数、改写重验、动作绑定审批、工具预算、会话终止与无原文审计。模板约束独立于策略，宽松策略或观察模式不能使模型突破注册的参数枚举。
- 模板/摘要校验发生在策略改写和审批后、工具执行计数提交前；执行器启动前再次校验。非法 JSON、未知/缺失参数、参数注入、权限/审批拒绝、准备阶段摘要变化不会启动程序。
- 使用 argv 直接启动，清空父进程环境，关闭 stdin，合并并有界收集 stdout/stderr。只交付退出码零且有效 UTF-8 的完整文本，经 post_tool_call 检查/改写后进入模型或调用方；无原始增量回调。
- 默认超时 5000ms、输出 65536 字节、单个模板实例并发容量 2；可配置上限分别为 30000ms、1048576 字节、32。超过容量立即拒绝，不创建等待队列。
- 超时、会话终止、取消/线程中断和输出失败尽力终止已启动的主进程及可观察后代，关闭管道。失败使用稳定错误码，不返回 stderr、原始命令或底层错误消息。
- 同步 execute、executeWithContext 和异步 executeAsync 进入同一治理路径。Builder.commandTool 自动生成枚举 schema；guardCommand 提供高级入口。异步阻塞等待放到已有有限工作池，不占模型响应线程；额外上下文桥不重复治理或计数。
- 真实子进程、真实 AI Services 和现有模型/工具/数据回归测试，在 JDK 17/21 验证。拒绝以实际启动标记不存在为证据；改写以真实输出和模型收到的结果为证据。

## 源码 spike 与选型

复用 Java 17 [ProcessBuilder](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/lang/ProcessBuilder.html)、[Process API](https://docs.oracle.com/en/java/javase/17/core/process-api1.html) 和现有治理内核。JDK 自带 argv、独立工作目录、环境控制、流管道及进程句柄，足以执行固定受信任工具；本轮不增加命令字符串解析器或脚本引擎。核对固定版本发布源码的 LangChain4j ToolExecutor：异步默认明确拒绝，新增执行器显式接入有界异步工作池。

评估 [gVisor](https://gvisor.dev/docs/)：它提供 Linux 容器应用内核隔离，适合不可信程序，需要宿主部署容器运行时、文件挂载/网络和资源策略。当前开发及验证环境为 macOS，不把未部署、未实测的 Linux 沙箱集成当作已交付。后续如果需要模型生成代码，将另行集成隔离后端并进行逃逸、文件、网络和资源测试。JDK 无新增第三方运行库；gVisor 仅作为方案参考，未复制其代码。

## 安全边界

固定程序、固定参数和枚举选项必须经宿主审核。例如不能把 `sh -c`、解释器 `-e` 或执行任意文件的选项开放给模型。允许的选项也可能触发程序自身的危险能力，SDK 不理解所有 CLI 语义。

此入口不是 JVM 或操作系统沙箱：子进程仍拥有宿主用户的文件/网络权限，没有 CPU、内存、磁盘、系统调用或进程组硬隔离。程序摘要只校验指定可执行文件，不覆盖脚本解释器加载的脚本、JAR、动态库、配置、文件系统内容或程序来源。宿主须使用可信摘要及不可变部署，避免摘要检查与启动之间的替换竞态；目录路径不是目录内容完整性证明。对注册时现有程序自动计算摘要仅适合本机演示，不能证明来源可信。

后代枚举与终止是尽力清理，不能保证捕获已脱离/重设父子关系的进程，不能撤销已发生副作用。若已脱离的后代持续持有 stdout 管道，SDK 返回拒绝后，守护读取线程可能延迟退出；实例容量不是操作系统进程/线程数硬限额。保留原始 Java 工具和任意宿主代码的能力，不自动识别、拦截同 JVM 中所有 Runtime.exec、ProcessBuilder、反射或动态加载操作。生产不可信代码执行仍需要独立隔离后端。
