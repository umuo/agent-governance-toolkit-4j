# 首期需求规格 v0.1

本文件保留 v0.1 首期基线。v0.2 异步与并发扩展见 [异步需求](async-requirements.md)，当前 v0.3 见 [严格缓冲流式需求](streaming-requirements.md)。

状态：2026-10-13 确认的首期范围。功能定义与验收以本文件为准；实际验证记录见 [验收报告](verification.md)。

## 产品目标

构建纯 Java Agent 运行时治理 SDK，先适配 LangChain4j。功能呈现和使用方式遵循微软 AGT 的「运行时 + 策略 + 会话 + guard / govern 适配器」。Guardrails 可以是内部实现手段，不能成为产品功能边界。

首期交付：可信会话 → 输入检查 → 每次模型与工具前后检查 → 最终输出检查 → 审计 → 会话结束。禁止工具不得执行，改写必须实际落实，未批准动作不得执行，每次决策可追溯到会话、动作和策略版本。

采用独立 Java API 和策略格式，不承诺微软 ACS manifest 或跨语言身份、签名、审批和审计协议互通。

## 产品组成与接口

- `agt-core`：AgentControl、HostSession、PolicyEvaluator、ApprovalResolver、AuditSink；不依赖 AI 框架。
- `agt-langchain4j`：依赖 LangChain4j，提供 guardModel、guardTool 和受控 AI Services Builder。
- 示例：合法查询、越权拒绝、参数与结果改写、审批允许与拒绝、预算耗尽。

推荐通过 Builder 注册模型、@Tool 对象、显式 ToolExecutor 或动态 ToolProvider，自动组装完整受控调用链。高级入口提供单独装饰器，必须明确各入口实际覆盖的干预点。仅包装已有 AI Service 不能宣称其内部模型、工具已受控。

## 功能要求

| 编号 | 必须满足的行为 |
|---|---|
| FR01 生命周期 | 支持 agent_startup、input、pre_model_call、post_model_call、pre_tool_call、post_tool_call、output、agent_shutdown；启动/结束按会话，输入/输出按 Agent 调用，模型/工具按每次调用。缺少必需策略绑定时拒绝构建。 |
| FR02 策略 | 本地 YAML 和 Java 编程式策略共用评估链；启动加载并固定版本；非法配置、重复字段、未知规则明确失败；不执行任意脚本、SpEL 或 Java 表达式。 |
| FR03 裁决 | ALLOW、DENY、TRANSFORM；审批附着在拒绝结果上，警告作为附加信息；默认 ENFORCE；EVALUATE_ONLY 记录裁决、继续原值，不执行改写也不宣称已阻断。 |
| FR04 工具权限 | 默认拒绝未允许工具；检查权限与 JSON 参数的类型、必填项、枚举、数值范围、长度及未知字段；拒绝畸形、重复键、异常深度和容量超限输入。 |
| FR05 可信身份 | 宿主认证入口提供 Agent、用户、租户和权限；不从模型输入或输出建立可信身份；参数可以绑定上下文；多会话隔离，关闭后不可使用。 |
| FR06 内容 | 模型前检查系统/历史/增强消息/工具返回；模型返回交给后续处理前检查；工具返回进入模型或调用方前检查；提供字面规则和自定义策略 SPI，不承诺通用语义注入识别。 |
| FR07 改写 | 改写后的值进入实际执行/交付；不支持的类型、元数据变更或可信字段变更必须拒绝；改写后重新校验工具参数和授权；支持文本、工具 JSON 参数与文本结果。 |
| FR08 审批 | 提供 SPI 与演示；绑定身份、会话、动作、有效参数、策略版本；执行前核对绑定及会话有效性；缺失、拒绝、超时、异常、动作变化或审批重放均拒绝。等待有界且可取消。 |
| FR09 预算 | 每会话限制模型调用、工具执行和期限；原子预占，执行前拒绝释放，执行后失败仍计数；重复和 SDK 层重试计入次数；Token 缺失标记未知，不承诺费用硬限额。 |
| FR10 故障终止 | 策略、审批、适配错误默认关闭路径；安全拒绝后不能被框架错误处理器恢复；撤销/过期阻止后续动作和结果交付，不宣称安全终止任意 Java 工具。 |
| FR11 审计 | 记录会话、Agent、动作 ID、干预点、版本、裁决、改写、审批、执行结果、耗时；不默认保存内容原文/个人信息；JSONL 与 SPI；必需审计失败停止后续动作，区分执行前后失败。 |
| FR12 适配 | 同步文本、顺序工具；覆盖 execute/executeWithContext、@Tool、自定义执行器、动态提供器与立即返回；保留名称、调用 ID、宿主注入参数和原生返回语义。未支持形态明确拒绝。 |

## 验收标准

1. 合法查询完成模型 → 工具 → 模型循环，八类干预点按序触发且不重复计数。
2. 工具越权、非法参数、缺失会话身份、跨租户参数的副作用为零。
3. 参数改写实际到达工具，结果改写实际到达模型与调用方，其他返回字段不夹带原值。
4. 即使错误处理器将安全异常变成文本，也不得再次执行模型/工具或通过立即返回绕过输出检查。
5. 审批允许、拒绝、超时、异常、动作绑定不符和重复使用结果正确。
6. 多会话隔离，预算并发预占、执行失败计费、撤销和关闭行为可验证。
7. 各同步入口、动态和立即返回工具均受控；输入、模型输出、工具输出与最终输出各自可拒绝。
8. 异步、流式、多模态、并发工具和复杂返回明确失败；无静默旁路。
9. 审计关联完整、无敏感原文；执行前后审计故障可复现。

## 技术与后续边界

Maven 多模块，Java 17 编译基线，验证 JDK 17/21，不用 preview API；固定 LangChain4j 1.20.0。纯 Java 结构化策略，首期不使用 Rust FFI、OPA、Cedar、Byte Buddy、Spring Boot Starter 或独立审批服务。

参考已有 hook 项目的严格 JSON、上下文和故障关闭设计，不直接复用布尔裁决内核作为改写/审批引擎。不预设未经测量的性能承诺，不声称摘要跨语言一致、审计防篡改或 OWASP 完整覆盖。

后续依次补充异步/并发工具、严格缓冲流式、RAG 检索前权限与记忆读写治理，再考虑 MCP、多 Agent 委托、供应链和分布式可靠性。当前 RAG/Memory 内容检查不等于数据访问授权。工具后置拒绝不能撤销已有副作用。
