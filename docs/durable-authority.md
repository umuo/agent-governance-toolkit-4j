# 持久化授权与共享用量账本

可选模块 `agt-delegation-jdbc` 把同一根任务的授权、认领、防重放、共享调用次数、模型用量和数据流检查点放进 JDBC 事务。多个授权服务实例连接同一数据库和相同命名空间时，使用根任务行锁协调；新建实例或 JVM 不会获得一份新额度。该模块仍是实验能力，默认不启用。

本轮复用既有 `GrantRegistry`、信息流引擎、用量计量协议和 JDBC，不新增策略语言或自制数据库。测试继续采用 [H2](https://github.com/h2database/h2database) 2.4.240（MPL-2.0 / EPL-1.0），仅为测试依赖；生产模块不附带 JDBC 驱动。外部关系授权服务的适用边界见[补齐计划](security-hardening-plan.md#现成方案检查)，它们不直接替代运行中预占、未知用量和结果交付状态。

## 接入

应用显式添加 `io.agt:agt-delegation-jdbc:0.6.0-SNAPSHOT`，并提供受信任的数据源、认证和密钥：

```java
var clock = Clock.systemUTC();
var labels = new JdbcLabelStore(labelDataSource, 2); // 可选；需要实例标签时同时配置。
labels.initializeSchema();
var registry = new JdbcGrantRegistry(authorityDataSource,
        "production-authority", clock, labels,
        2, JdbcGrantRegistry.DEFAULT_MAXIMUM_BYTES);
registry.initializeSchema(); // 由可信宿主显式初始化或迁移，不在请求失败后自动重建。

try (var authority = new DelegationAuthority(
        issuer, keyId, signingPrivateKey, registry, clock);
     var root = authority.register(sourceSession)) {
    // 继续使用既有签名授权与 GrantStatusService 协议。
    // 接收者通过宿主认证的服务身份访问授权服务，不直接拿数据库凭据。
}
```

若不使用持久实例标签，`catalog` 传 `null`。开启标签时，源 `AgentControl` 与注册表须绑定同一 `LabelStore` 目录；使用自定义目录还须实现稳定的 `catalogIdentity()`。JDBC 目录具有持久 UUID，不能把另一份目录误当成原目录重新绑定。无目录的原任务可以没有实例标签，但不会因此忽略根任务已经累积的敏感等级。

| 参数 | 含义与约束 |
| --- | --- |
| `authorityName` | 受信任的授权命名空间；同一协调集群使用相同值，不从模型参数取值 |
| `clock` | 宿主时钟；每次事务使用数据库已观察时间与当前时间的较大值，避免已观察到的到期被时钟回退复活 |
| `catalog` | 原任务的稳定标签目录；没有目录时显式传 `null`，不能在恢复失败后临时替换为空目录 |
| `statementTimeoutSeconds` | 每条 SQL 超时，范围 1–30 秒；不替代连接池的获取连接/登录/网络期限 |
| `maximumCheckpointBytes` | 每根任务的序列化容量，默认 64 MiB，允许 1–512 MiB；所有实例应统一配置 |

目录访问可能在授权事务持有连接时再获取一个标签连接；宿主应提供独立连接池或足够容量，避免单连接池自锁。授权服务和接收服务的身份认证、TLS、密钥轮换及数据库权限仍由宿主配置，详见[远端委托](remote-delegation.md)。

## 交接、事务与重启

交接要求源任务没有排队、执行中或后置检查尚未结束的受控操作，也没有未决模型预占。失败返回 `delegation_operations_inflight_denied` 或既有用量错误，未发生交接时原任务仍可继续。成功后源任务不能再执行新的本机操作；它的用量查询、数据流快照和输出校验绑定共享权威状态，子节点新接触的敏感来源也会约束父节点的最终输出。

数据库表 `agt_authority_root` 保存根任务检查点、递增版本、已观察时间和容量阻断标记；`agt_authority_member` 映射所有授权到根任务。`authorityName + taskId` 唯一，重复注册不能清零消费。每次操作加载有界检查点，在事务中锁定根行、重建纯状态、处理租约到期、执行授权判断并提交。检查点包括：

- 授权链、真实会话绑定、租约秘密摘要、撤销/结束状态及已准入动作摘要。
- 交接前已结算消费、共享剩余额度、每次模型预占/dispatch/结算/关闭状态与固定价格配置。
- 当前数据等级、来源、完成步骤、已观察的实例版本及稳定目录身份。

恢复不执行工具、模型、记忆写入或用户回调，不重放副作用，也不把失效租约自动续成新租约。重启后仍须有存活源任务和有效原租约；源宿主失联会按原租约到期。持久化不代表崩溃任务可以自动恢复执行。

业务拒绝也可能产生必须保留的状态，例如超时清理、模型超出约定上界或未知费用冻结。因此这类拒绝会连同变化提交，不回滚成允许状态。SQL 提交结果未知时返回 `delegation_registry_unavailable`，不自动重试或退款；调用方不能因为没收到准入回执就直接执行。事务完成时已超过授权期限也拒绝准入，并记录观察到的时间。

若更新后的检查点无法写入容量上限，数据库会持久设置根任务阻断标记，后续即使用更大容量的新实例也拒绝继续执行。此时旧检查点不能作为最新余额使用，检查接口同样拒绝；需要可信运维核对，当前没有自动解除阻断或安全续跑接口。不能通过清空表、调大容量或重新发放同一任务来自动消除未知消费。

## 结束后的核对

`registry.inspect(rootId, authenticatedReader)` 是宿主专用诊断接口，可在授权结束或 Token 到期后查看调用次数、用量、未知预占和数据流。调用者必须由宿主认证，具有 `governance:inspect`，并与原任务的 `tenantId`、`principalId` 一致。它不在接收者的 `GrantStatusService` 协议中，不接受模型自行声明的身份。

用量、价格和调用次数不会随子会话关闭而清零。结束前的预占可以释放；已经 dispatch 而结果未知时保留上界额度并冻结根任务。核对接口不会解除冻结，也不代表 Provider 已取消请求或账单已经确认。调用次数表示交接后的权威准入；交接前已消费次数已从可转移额度扣除，用量快照则包含此前已结算金额。

## 已验证与限制

测试覆盖文件数据库重新打开、多个独立注册表实例并发认领/预占、重复注册、跨目录替换拒绝、损坏检查点拒绝、结算错误持久保留、期限回退、提交回执丢失，以及结束后的权限隔离。独立 JVM 通过本机 H2 TCP 测试数据库协调，实际走 SDK 签名接收与受控工具/模型路径：

- 两个工作 JVM 共享 3 次工具额度；第 4 次被拒绝，原生工具总计执行 3 次。
- 两次模型调用各结算 50 Token，共 100 Token / 固定测试价格 USD 0.00012；第 3 次需要预占 150 Token，在总额 200 下拒绝，不进入原生模型函数。
- 强制杀掉已 dispatch 的工作 JVM，过期处理后保留 150 Token、1 次未知调用；兄弟节点的原生模型执行次数保持为 0。
- 新启动的只读 JVM 从数据库读取已结束任务，仍看到累计消费或未知预占。

这些模型函数为可控测试端点；官方客户端输出限制及跨 JVM 模型请求已在[分布式用量阶段](model-usage-budget.md)单独验证，本轮没有把测试价格说成生产账单。

当前仅验证 H2 的 SQL、事务与多 JVM 协调。使用 `BLOB`、`SELECT ... FOR UPDATE` 等语句，其他数据库需要适配与验收。每次请求保存完整根任务检查点，尚无大图、高吞吐、数据库主从切换或生产高可用保证。连接池、备份、数据加密与保留策略仍需部署方配置。

固定 DTO、有界 JSON、域内一致性检查和 SHA-256 校验和用于发现损坏；没有 Java 原生反序列化或多态可执行类型。校验和不是不可伪造审计签名，不能防范有数据库管理权限的人修改状态并重算摘要或整体回滚备份。检查点不保存租约明文、签名私钥或模型/工具正文，但会包含身份、资源及策略元数据，必须按敏感控制面数据管理。

持久来源标签与授权检查点目前是不同事务；标签可能保守地先提高，即使后续授权事务失败也不自动降低。这里不提供副作用原子提交、账单核对、跨平台沙箱验收、生产 IAM 或可靠外部取消确认。剩余工作继续按[安全能力补齐计划](security-hardening-plan.md)推进。
